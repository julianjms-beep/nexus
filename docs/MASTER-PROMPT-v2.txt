NEXUS OS must support three execution environments.

3.1 Local execution

Agents and services execute on the user’s computer.

Initial target:

* macOS.

Subsequent targets:

* Windows.
* Linux.

* Authorized filesystem access.
* Application launching.
* Development tools.
* Local models.
* Voice processing.
* Project management.
* Agent execution.
* Workflow execution.
* Local databases.

3.2 Remote execution

Agents execute on remote servers or isolated workers.

Requirements:

* Secure worker registration.
* Worker identity verification.
* Encrypted communications.
* Task distribution.
* Remote execution monitoring.
* Execution cancellation.
* Resource limits.
* Cost controls.
* Persistent task state.
* Artifact retrieval.
* Execution logs.

Remote workers must not automatically inherit local filesystem access or credentials.

3.3 Hybrid execution

NEXUS must coordinate local and remote agents.

The orchestrator should select an execution environment based on:

* User preference.
* Available hardware.
* Task requirements.
* Security classification.
* Data sensitivity.
* Estimated cost.
* Worker availability.

Users must be able to override automatic selection.

3.4 Long-term operating system

A bootable Linux-based NEXUS distribution may be developed in a later phase.

Do not prioritize kernel development or a custom Linux distribution before the desktop platform is functional and validated.

14. NEXUS SECURITY — SYSTEM-WIDE TRUST LAYER

Security must be foundational.

Implement a default-deny permission model.

Every sensitive operation must pass through a centralized authorization service.

Permission categories

Low risk

* Open an application.
* Open a website.
* Read non-sensitive system metrics.

Medium risk

* Modify authorized project files.
* Execute approved development commands.
* Install reviewed Skills.

High risk

* Delete important files.
* Access credentials.
* Modify security settings.
* Execute privileged commands.
* Deploy to production.
* Perform financial transactions.

High-risk actions require explicit approval.

Security architecture

Implement:

* Least-privilege execution.
* Filesystem boundaries.
* Secure path resolution.
* Network restrictions.
* Credential isolation.
* Sandbox enforcement.
* Audit logging.
* Resource quotas.
* Approval interfaces.
* Secure remote worker authentication.

Do not use string-prefix comparisons as the sole method of filesystem authorization.

Do not assume that a subprocess is sandboxed.

Do not implement approval functions that always return true.

Do not rely exclusively on model-generated judgments for security decisions.
